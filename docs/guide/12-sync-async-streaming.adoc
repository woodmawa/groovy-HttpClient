== Sync, Async and Streaming

Every request can be made three ways. They differ in *when you get control back* and *where the body goes*:

[cols="1,3,3"]
|===
| |You get back |The body

|Sync (`getSync`) |The result, when it is complete |In memory
|Async (`get`) |A `CompletableFuture`, immediately |In memory
|Streaming (`download`, `lines`, `sse`, `ndjson`) |A `StreamResult` (or its future) when the body has been delivered |To a file, a stream or your callback, piece by piece
|===

=== Synchronous: the default choice

[source,groovy]
----
def r = client.getSync('/orders/42')
----

Because every request runs on a virtual thread, blocking is cheap: a sync call in a web request handler, a batch job or a script ties up no platform thread. Use sync calls unless you have one of the reasons below to do otherwise; the code is simpler and stack traces are clearer.

`++*Sync++` methods wait at most 30 seconds by default; pass a `Duration` as the last argument to change that. The request's own timeout (<<client-timeouts>>) bounds the request separately.

[source,groovy]
----
def r = client.getSync('/reports/annual', null, Duration.ofMinutes(2))
----

=== Asynchronous: for concurrency and composition

The same verbs without `Sync` return a `CompletableFuture` at once. Use them when:

* *you call several services, or one service many times, and the calls are independent* -- start them all, then wait once;
* *you compose calls* -- the second depends on the first;
* *your framework is asynchronous* -- return the future rather than blocking on it.

[source,groovy]
----
def client = new GroovyHttpClient('https://jsonplaceholder.typicode.com')

// fan out: ten requests in flight together
def futures = (1..10).collect { id -> client.get("/posts/${id}") }
def titles = futures*.join().collect { it.json.title }

// compose: the second request needs the first's answer
client.get('/posts/1')
      .thenCompose { r -> client.get("/users/${r.json.userId}") }
      .thenAccept { r -> println "Written by ${r.json.name}" }
      .join()

// different services at once
def (user, orders) = [users.get('/users/7'), orders.get('/orders?user=7')]*.join()
----

A failed future completes exceptionally with the same exception the sync method would throw; `join()` wraps it in `CompletionException`, so prefer handling failures in the chain (`exceptionally`, `handle`) or with a `response { exception {...} }` handler.

TIP: Limit how many requests you start at once when fanning out over a large list -- the server, not the client, is usually the bottleneck. A `java.util.concurrent.Semaphore` around each call is enough.

=== Streaming: for big or endless bodies

Streaming verbs never hold the whole body in memory. Use them when:

* *the body is large* -- exports, backups, media: `download` writes it to a file;
* *the body never ends, or arrives over time* -- event feeds, log tails, AI token streams: `sse`, `lines`, `ndjson` hand you each item as it arrives;
* *you want to start work before the last byte arrives.*

[source,groovy]
----
def bin = new GroovyHttpClient('https://httpbin.org')

// a download, written to a temporary file and moved into place when complete
bin.downloadSync('/image/png', Path.of('image.png'))

// newline-delimited JSON, one parsed value at a time
bin.ndjsonSync('/stream/5') { Map record -> println record.id }

// Server-Sent Events from a long-running stream: stop after ten
def wiki = new GroovyHttpClient('https://stream.wikimedia.org')
wiki.sseSync('/v2/stream/recentchange', { header 'User-Agent', 'my-app/1.0 (me@example.com)' }) { SseEvent e, StreamControl c ->
    println e.data.take(80)
    if (c.items == 10) c.stop()
}
----

Streaming verbs come in sync and async forms too (`download` / `downloadSync`, `sse` / `sseSync`...). Uploads stream as well: `body(Path)` sends a file without loading it. <<streaming>> covers limits, timeouts, stopping and retry rules.

=== Decision guide

[cols="3,2"]
|===
|Situation |Use

|One call, result needed now (web handler, job step, script) |`getSync`
|Several independent calls |`get` ... then `join`
|A call that depends on another |`get(...).thenCompose { ... }`
|An asynchronous framework |`get`, returning the future
|A response bigger than you want in memory |`download` / `downloadSync`
|Events, logs or records arriving over time |`sse`, `lines`, `ndjson`
|A large upload |`body(Path)` or `body(InputStream, type)` in any verb
|===
