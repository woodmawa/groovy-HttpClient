[[authentication]]
== Authentication

=== The schemes

[source,groovy]
----
def bin = GroovyHttpClient.builder('https://httpbin.org').auth { basic 'user', 'passwd' }.build()
assert bin.getSync('/basic-auth/user/passwd').json.authenticated

auth { basic 'user', 'password' }                         // RFC 7617, UTF-8
auth { bearer 'eyJhbGciOi...' }                            // a fixed token
auth { bearer { -> vault.read('orders-token') } }          // a supplier, asked on every attempt
auth { apiKey header: 'X-API-Key', value: key }            // in a header
auth { apiKey query: 'api_key', value: key }               // in the query string
auth {                                                     // OAuth2 client credentials
    oauth2 {
        tokenUrl 'https://login.example.com/oauth2/token'
        clientId 'orders-service'
        clientSecret secret
        scope 'orders.read', 'orders.write'
    }
}
----

Declare credentials on the builder (`.auth { }`), on a client (`client.auth { }`; `null` clears), or on one request (`auth { }` in its closure, or `noAuth()` to send none). An `auth { }` block holds one scheme. Credentials are applied on each attempt, so retries pick up a refreshed token; if a request already has the header (or query parameter), yours wins.

=== Where credentials go

Credentials are sent only to the base URL's origin -- same scheme, host and port. A request to another host, even an allowed one, gets none unless you name it:

[source,groovy]
----
auth {
    bearer token
    authHosts 'files.example.com'
}
----

On a redirect to another origin, `Authorization`, `Proxy-Authorization`, `Cookie` and a custom API-key header are removed. Secrets never appear in `toString()`, exception messages or logs.

[[oauth2]]
=== OAuth2 client credentials

* The token is fetched on first use and cached until `expires_in` minus 60 seconds. Concurrent requests share one token request.
* A 401 invalidates the token; the client fetches a new one and re-sends the request once, if its body can be re-sent.
* The client authenticates with `client_secret_basic`; use `clientAuth 'post'` for `client_secret_post`.
* Other options: `skew Duration.ofSeconds(120)` to refresh earlier, `param 'audience', '...'` for extra form parameters.
* The token endpoint must be HTTPS, except on a loopback host or when the client allows insecure connections (for local test servers).
* The token request uses the client's TLS settings, trust store and proxy, but not its allowed hosts, retry policy or interceptors -- you do not need to add the identity provider to `allowedHosts`.

A failed token request raises `AuthenticationException` with the token endpoint's status and its OAuth `error` code, never the body, the secret or a token:

----
OAuth2 token request to https://login.example.com/oauth2/token failed: HTTP 401 (invalid_client)
----

Digest authentication is not supported. For other schemes, set the `Authorization` header in an interceptor (<<interceptors>>).
