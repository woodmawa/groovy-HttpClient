[[troubleshooting]]
== Troubleshooting

Common symptoms, their usual cause, and the fix. If yours is not here, turn on `enableLogging(true)` (<<logging>>) and check the exception's fields (<<http-response-exception>>).

[cols="2,3,3"]
|===
|Symptom |Cause |Fix

|`javax.net.ssl.SSLHandshakeException: PKIX path building failed`
|The server's certificate is not trusted by the JVM trust store. Common after upgrading from 1.x, where the String constructor and `testing()` trusted every certificate.
|Trust the issuing CA: `builder(url).trustStore(caStore)`, `withOverrides(trustStore: caStore)`, or an `sslContext`. Use `trustAll()` only for throwaway local debugging.

|`SSLHandshakeException` / connection reset against an mTLS endpoint
|The server requires a client certificate and none was sent.
|Supply `keyManagers` (builder `.keyManagers(kms)` or `withOverrides(keyManagers: kms)`).

|`IllegalArgumentException: Unknown SecurityConfig setting(s): [...]`
|A misspelt or unsupported key passed to `withOverrides` or the constructor.
|Use one of the names listed in the message. 1.x ignored such keys silently.

|`GroovyHttpClient.RedirectRejectedException`
|A redirect pointed to a host outside `allowedHosts`, from HTTPS to HTTP, to a non-HTTP scheme, or exceeded `maxRedirects`.
|Add the legitimate target host to `allowedHosts`, or raise `maxRedirects`. Never "fix" an HTTPS -> HTTP redirect on the client.

|A 3xx response instead of the final resource
|`allowRedirects(false)` is set (it is honoured since 2.0.0).
|Remove the setting if you want redirects followed.

|`ResponseTooLargeException` (status 413) that the server never sent
|The response body exceeded `maxResponseBytes` (decompressed bytes when compression is on); the client stopped reading.
|Raise the limit for that request with `maxResponseBytes n` in the request closure, or stream the body to a file with `download(...)` (<<streaming>>).

|`HttpResponseException` message no longer shows the response body
|Since 2.1 the message is log-safe and carries no body.
|Read `e.responseBody`, `e.bodyAs(Type)` or `e.problem`, or set `errorBodyPreviewChars` (<<http-response-exception>>).

|`IllegalStateException: A response handler returned ...`
|A `response { }` handler returned a value from an untyped verb, which returns `HttpClientResponse`.
|Use the typed verb, e.g. `getSync(Order, path)` or `getSync(Object, path)` (<<response-handlers>>).

|`ContentParseException` naming a class and a key
|Typed mapping without Jackson found a JSON key with no matching property.
|Add the property, or put Jackson on the classpath and configure it to ignore unknown properties (<<codecs-config>>).

|`ContentDecodingException`
|A body labelled `gzip` or `deflate` is truncated, corrupt or not compressed at all.
|A server or intermediary problem; turn `compression` off for that endpoint while it is fixed.

|Response body is binary gibberish with `Content-Encoding: gzip`
|Compression is off, or you set `Accept-Encoding` yourself, so the client did not decode it.
|Turn on `compression(true)` and leave `Accept-Encoding` to the client (<<compression>>).

|`StreamItemTooLargeException`
|One line, event or NDJSON value exceeded `maxStreamItemBytes` (default 1 MiB).
|Raise `maxStreamItemBytes` if the items are legitimately that large.

|A long-lived SSE or line stream ends with `ResponseTooLargeException`
|The whole stream reached `maxResponseBytes`.
|Raise it for that request: `{ maxResponseBytes Long.MAX_VALUE }` (<<event-streams>>).

|`RedirectRejectedException: A 307 redirect ... one-shot body`
|An `InputStream` or `Publisher` upload was redirected with 307/308, which would need the body sent twice.
|Upload from a `Path` or `byte[]`, or upload to the final URL directly (<<uploads>>).

|An upload from a `SubmissionPublisher` arrives empty
|A hot publisher drops items emitted before the client subscribes.
|Start emitting once `numberOfSubscribers > 0`, or use a cold publisher.

|`AuthenticationException: OAuth2 token request ... failed: HTTP 401 (invalid_client)`
|The identity provider rejected the client id or secret, or the client authentication method.
|Check the credentials; try `clientAuth 'post'` if the provider wants `client_secret_post` (<<oauth2>>).

|`AuthenticationException: OAuth2 tokenUrl must be HTTPS`
|The token endpoint is plain HTTP on a non-loopback host.
|Use the provider's HTTPS endpoint.

|No `Authorization` header on a request to another host
|Credentials go only to the base URL's origin.
|Add the host with `authHosts(...)` inside `auth { }` (<<authentication>>).

|`AuthenticationException: The proxy refused the HTTPS tunnel (407 ...)`
|The proxy wants credentials: none were set, they are wrong, or the JDK dropped Basic credentials from `CONNECT`.
|Set `proxyAuth`, and start the JVM with `-Djdk.http.auth.tunneling.disabledSchemes=""` (<<proxy-auth>>).

|`IllegalArgumentException: SOCKS proxies are not supported`
|A SOCKS proxy was configured; the JDK `HttpClient` would silently connect directly.
|Use an HTTP proxy (<<socks>>).

|WARN: `The JVM proxy settings select a SOCKS proxy ... Requests are going direct`
|`socksProxyHost` (or system proxy settings) pick a SOCKS proxy, which the JDK `HttpClient` ignores.
|Configure an HTTP proxy with `proxy(host, port)`, or `noProxy()` if direct is intended.

|`testFixtures("io.github.woodmawa:groovy-httpclient:...")` does not resolve
|Using 2.0 (no fixtures published) or a Maven build.
|Use 2.1 or later; in Maven use `<classifier>test-fixtures</classifier>` (<<published-fixtures>>).

|`IllegalArgumentException: Absolute URLs disabled by configuration` / `Target host not allowed`
|An absolute URL was passed while `allowAbsoluteUrls` is off, or its host isn't in `allowedHosts`.
|Use a path relative to the base URL, or enable `allowAbsoluteUrls` and list the host.

|`IllegalArgumentException: Invalid value for cookie ...`
|The cookie value contains `;`, `,`, whitespace, quotes, backslash or control characters.
|URL-encode or Base64 the value.

|`IllegalArgumentException: MultipartPart.filename must not contain CR, LF or NUL`
|A part name, filename or content type carries line breaks, often from unsanitised user input.
|Sanitise the value; take only the file name component of user-supplied paths.

|`MissingMethodException` inside a request closure
|A call that the request DSL doesn't support. 1.x silently ignored it.
|See the request DSL table in <<request-configuration>>.

|`GroovyHttpClient.CircuitOpenException`
|The breaker is OPEN, or HALF_OPEN with its single probe already in flight.
|Back off or serve a fallback; tune `failureThreshold` / `resetTimeoutMs`.

|A POST is not retried despite a retry policy
|Since 2.0.0, non-idempotent methods are retried only with `retryNonIdempotent(true)`.
|Opt in only when the server de-duplicates (e.g. an `Idempotency-Key`).

|No log output with `enableLogging(true)`
|No SLF4J binding on the classpath (2.0.0 no longer ships logback), or the `org.softwood.http.GroovyHttpClient` logger is above INFO.
|Add a binding such as `logback-classic` and configure the logger level.

|`IllegalStateException: HTTP/3-only ... requires JDK 26`
|`Http3Discovery.HTTP_3_URI_ONLY` on a JDK without HTTP/3.
|Run on JDK 26+, or use `ANY` / `ALT_SVC`, which fall back to HTTP/2.

|`response.httpVersion` is `HTTP_2` although `http3()` is set
|JDK < 26 (see the WARN at client creation), the server doesn't offer HTTP/3, or UDP 443 is blocked (common behind corporate firewalls).
|Expected fallback with `ANY` / `ALT_SVC`. To check the path, try `HTTP_3_URI_ONLY` against the server.

|`No Awaitable adapter found for type ...` in your own Groovy 6 code
|A method of yours named `await(...)` is shadowed by Groovy 6's built-in `await`.
|Rename the method.
|===
