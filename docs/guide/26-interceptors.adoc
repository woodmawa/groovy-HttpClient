[[interceptors]]
== Interceptors

An interceptor wraps every request attempt, for logging, metrics, tracing or short-circuiting:

[source,groovy]
----
client.addInterceptor { ctx, next ->
    long started = System.nanoTime()
    next.call(ctx).thenApply { resp ->
        metrics.timer(ctx.method).record(System.nanoTime() - started)
        resp
    }
}
----

* `ctx` carries the request's `method`, `uri` and `attempt` number.
* Call `next.call(ctx)` to continue; it returns a `CompletableFuture` of the response. Return your own completed future to answer without a network call (a cache, for example).
* Interceptors run in the order added: the first added is outermost, so it sees the request first and the response last.
* They run inside the retry loop, once per attempt, and receive 4xx and 5xx responses as responses, not exceptions.
* An exception thrown by an interceptor fails the request with that exception.
* Credentials from `auth { }` are added after the interceptors, so an interceptor never sees or logs them.

=== Per-attempt timings with Micrometer

The client's own metrics (<<metrics>>) are totals per client. For latency percentiles per method, time each attempt in an interceptor:

[source,groovy]
----
client.addInterceptor { ctx, next ->
    def sample = Timer.start(registry)
    next.call(ctx).whenComplete { resp, err ->
        sample.stop(registry.timer('http.client.attempts',
                'method', ctx.method, 'status', resp ? String.valueOf(resp.statusCode) : 'error'))
    }
}
----
