== Introduction

The {project-name} is a Groovy DSL for making HTTP requests, built on the JDK's own `java.net.http.HttpClient`. You describe a request in a closure and get back a response, a parsed value, or one of your own types:

[source,groovy]
----
def client = new GroovyHttpClient('https://httpbin.org')

def r = client.getSync('/get') { query(lang: 'groovy') }
assert r.statusCode == 200
assert r.json.args.lang == 'groovy'
----

It is usable from Groovy and Java, including statically compiled (`@CompileStatic`) Groovy.

=== Built on a modern platform

*Groovy 6 and Java 25.* The library needs Java 25 or later and Groovy 6. It is compiled to Java 25 bytecode and tested on JDK 25 and JDK 27.

*HTTP/3 with graceful fallback.* On JDK 26 and later the client can use HTTP/3 (QUIC). Where HTTP/3 is not available -- an older JDK, a server that does not offer it, a network that blocks UDP -- it falls back to HTTP/2, which in turn falls back to HTTP/1.1. You opt in with one call, and the same code runs everywhere:

[source,groovy]
----
def client = GroovyHttpClient.builder('https://quic.nginx.org').http3().build()
println client.getSync('/').httpVersion     // HTTP_3 on JDK 26+, HTTP_2 otherwise
----

*Virtual threads.* Every request runs on a virtual thread, so thousands of concurrent requests need no thread pool tuning, and a blocking call costs almost nothing.

=== Public HTTP/3 test endpoints

Endpoints maintained to serve HTTP/3, for trying the client, your tools or your proxies. The notes record what this client saw with JDK 27 in October 2026, using the default discovery mode:

[cols="2,3,3"]
|===
|Endpoint |Implementation |Seen with this client

|https://quic.nginx.org/[quic.nginx.org] |nginx's own HTTP/3 test site |HTTP/3 from the first request
|https://cloudflare-quic.com/[cloudflare-quic.com] |Cloudflare's quiche; shows the `Alt-Svc` upgrade |HTTP/2 first, HTTP/3 from the second request
|https://www.cloudflare.com/[www.cloudflare.com] |Cloudflare production |HTTP/2 first, HTTP/3 from the second request
|https://www.litespeedtech.com/[www.litespeedtech.com] |LiteSpeed's `lsquic` |HTTP/2 only; the QUIC handshake failed
|===

Other major sites (`www.google.com`, `facebook.com`) serve HTTP/3 too, but in the UK and EU they may redirect to a cookie-consent host first -- which the client refuses unless you allow that host.

The "HTTP/2 first" pattern is normal: the JDK learns from the server's `Alt-Svc` header that HTTP/3 is available and uses it from the next request. <<http3>> explains the discovery modes.
