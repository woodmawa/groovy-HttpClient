[[multipart-uploads]]
= Multipart Uploads

== Overview

GroovyHttpClient provides comprehensive support for `multipart/form-data` uploads, enabling you to send files, binary data, and form fields in a single HTTP request. This is essential for file uploads, mixed content submission, and API integrations requiring complex payloads.

[quote]
____
Multipart uploads should be as simple as regular POST requests — no manual boundary management or byte manipulation required.
____

=== Key Features

* ✅ Two API styles: DSL-based and static builder
* ✅ Automatic boundary generation
* ✅ Support for text, JSON, and binary parts
* ✅ Custom content types per part
* ✅ Filename and encoding control
* ✅ Request header customization
* ✅ Asynchronous and synchronous operations
* ✅ Integration with retry and circuit breaker

== Understanding Multipart Requests

A multipart request consists of multiple "parts," each with:

[horizontal]
*Name*:: Form field name (required)
*Filename*:: Optional filename for file uploads
*Content-Type*:: MIME type of the part data
*Data*:: Binary content (bytes)

The HTTP client automatically handles:

* Boundary generation and formatting
* Content-Disposition headers
* CRLF line endings
* Proper Content-Type with boundary parameter

== DSL-Based Multipart

The DSL provides an intuitive, builder-style API for constructing multipart requests.

=== Basic DSL Upload

[source,groovy]
----
def response = client.postMultipartSync("/upload") {
    part {
        name "document"
        filename "report.pdf"
        contentType "application/pdf"
        data pdfBytes
    }
    
    part {
        name "description"
        content "Monthly sales report"
    }
}

assert response.statusCode == 201
----

=== Text Parts

Use the `content` method for text data:

[source,groovy]
----
client.postMultipartSync("/submit") {
    part {
        name "username"
        content "alice"
    }
    
    part {
        name "comment"
        content "This is a multiline\ncomment with special chars: é ñ ü"
    }
}
----

[TIP]
====
The `content` method automatically:

* Converts text to UTF-8 bytes
* Sets `Content-Type: text/plain; charset=UTF-8`
* Generates a filename if not specified
====

=== Binary Parts

For binary data, use the `data` method:

[source,groovy]
----
def imageBytes = new File("photo.jpg").bytes

client.postMultipartSync("/photos") {
    part {
        name "photo"
        filename "vacation.jpg"
        contentType "image/jpeg"
        data imageBytes
    }
    
    part {
        name "title"
        content "Summer Vacation 2025"
    }
}
----

=== JSON Parts

Submit JSON as part of a multipart request:

[source,groovy]
----
def metadata = [
    author: "Alice",
    tags: ["important", "reviewed"],
    date: "2025-01-24"
]

client.postMultipartSync("/documents") {
    part {
        name "file"
        filename "data.csv"
        contentType "text/csv"
        data csvBytes
    }
    
    part {
        name "metadata"
        filename "metadata.json"
        contentType "application/json; charset=UTF-8"
        content groovy.json.JsonOutput.toJson(metadata)
    }
}
----

=== Multiple Files

Upload multiple files in a single request:

[source,groovy]
----
def files = [
    [name: "file1.txt", bytes: file1Bytes],
    [name: "file2.pdf", bytes: file2Bytes],
    [name: "file3.jpg", bytes: file3Bytes]
]

client.postMultipartSync("/batch-upload") {
    files.each { f ->
        part {
            name "files"  // Same name for all parts
            filename f.name
            contentType guessMimeType(f.name)
            data f.bytes
        }
    }
    
    part {
        name "count"
        content files.size().toString()
    }
}
----

[NOTE]
====
Multiple parts with the same `name` are valid and represent array/multiple values — common for file upload APIs.
====

=== Adding Request Headers

Include custom headers alongside multipart data:

[source,groovy]
----
client.postMultipartSync("/secure-upload") {
    part {
        name "file"
        filename "secret.zip"
        contentType "application/zip"
        data zipBytes
    }
    
    // Request headers (not part headers)
    header "Authorization", "Bearer ${authToken}"
    header "X-Request-ID", UUID.randomUUID().toString()
}
----

=== Asynchronous DSL Upload

For non-blocking uploads:

[source,groovy]
----
import java.util.concurrent.CompletableFuture

CompletableFuture<HttpClientResponse> future = client.postMultipart("/upload") {
    part {
        name "document"
        filename "report.pdf"
        data pdfBytes
    }
}

future.thenAccept { response ->
    println "Upload complete: ${response.statusCode}"
    println "Response: ${response.json}"
}.exceptionally { error ->
    println "Upload failed: ${error.message}"
    null
}
----

== Static Builder API

For programmatic construction, use `MultipartPart` static methods.

=== Text Parts

[source,groovy]
----
import org.softwood.http.MultipartPart

def parts = [
    MultipartPart.text("username", "alice"),
    MultipartPart.text("email", "alice@example.com")
]

def response = client.postMultipartSync("/register", parts)
----

=== JSON Parts

[source,groovy]
----
def userData = [
    name: "Alice Smith",
    age: 30,
    roles: ["admin", "user"]
]

def parts = [
    MultipartPart.json("user", groovy.json.JsonOutput.toJson(userData))
]

client.postMultipartSync("/users", parts)
----

=== Binary Parts

[source,groovy]
----
def imageData = new File("photo.jpg").bytes

def parts = [
    MultipartPart.bytes("photo", "vacation.jpg", "image/jpeg", imageData),
    MultipartPart.text("caption", "Beautiful sunset")
]

client.postMultipartSync("/photos", parts)
----

=== Mixed Content

Combine different part types:

[source,groovy]
----
def csvData = new File("data.csv").bytes
def metadata = [processed: true, rows: 1000]

def parts = [
    MultipartPart.bytes("file", "data.csv", "text/csv", csvData),
    MultipartPart.json("metadata", groovy.json.JsonOutput.toJson(metadata)),
    MultipartPart.text("user_id", "12345")
]

def response = client.postMultipartSync("/import", parts)
assert response.statusCode == 200
----

=== With Request Configuration

Add headers or other configuration with the static API:

[source,groovy]
----
def parts = [
    MultipartPart.bytes("file", "secret.zip", "application/zip", zipBytes)
]

def response = client.postMultipartSync("/secure-upload", parts) { config ->
    config.header "Authorization", "Bearer ${token}"
    config.header "X-Correlation-ID", correlationId
    
    config.timeout Duration.ofMinutes(5)  // Long upload timeout
}
----

== Advanced Patterns

=== Large File Streaming

For very large files, load data incrementally:

[source,groovy]
----
// Read file in chunks
def file = new File("large-video.mp4")
def fileBytes = file.bytes  // Load entire file (consider streaming for huge files)

client.postMultipartSync("/videos", [
    MultipartPart.bytes("video", file.name, "video/mp4", fileBytes)
]) { config ->
    config.timeout Duration.ofMinutes(30)  // Extended timeout
}
----

[WARNING]
====
The current implementation loads all part data into memory. For files exceeding available RAM, consider:

* Splitting into smaller chunks
* Using direct Java `HttpClient` with streaming
* Implementing server-side chunked upload support
====

=== Progress Tracking

While GroovyHttpClient doesn't have built-in progress tracking, you can implement it via interceptors:

[source,groovy]
----
import java.util.concurrent.atomic.AtomicLong

def uploadedBytes = new AtomicLong(0)
def totalBytes = calculateTotalSize(parts)

client.addInterceptor { ctx, next ->
    // Track upload progress
    def startTime = System.currentTimeMillis()
    
    next.call(ctx).thenApply { response ->
        def elapsed = System.currentTimeMillis() - startTime
        println "Upload complete: ${totalBytes} bytes in ${elapsed}ms"
        response
    }
}

client.postMultipartSync("/upload", parts)
----

=== Dynamic Part Generation

Generate parts dynamically based on runtime conditions:

[source,groovy]
----
def files = findFilesToUpload()

client.postMultipartSync("/batch") {
    // Add metadata part
    part {
        name "metadata"
        contentType "application/json"
        content groovy.json.JsonOutput.toJson([
            count: files.size(),
            timestamp: System.currentTimeMillis()
        ])
    }
    
    // Add file parts dynamically
    files.eachWithIndex { file, idx ->
        part {
            name "file_${idx}"
            filename file.name
            contentType guessMimeType(file.name)
            data file.bytes
        }
    }
}
----

=== Conditional Part Inclusion

Include parts based on conditions:

[source,groovy]
----
client.postMultipartSync("/submit") {
    part {
        name "required_field"
        content "always present"
    }
    
    if (includeOptionalFile) {
        part {
            name "optional_file"
            filename "extra.pdf"
            data optionalBytes
        }
    }
    
    if (metadata) {
        part {
            name "metadata"
            contentType "application/json"
            content groovy.json.JsonOutput.toJson(metadata)
        }
    }
}
----

== Error Handling

=== Upload Failures

[source,groovy]
----
try {
    def response = client.postMultipartSync("/upload") {
        part {
            name "file"
            filename "data.csv"
            data csvBytes
        }
    }
    
    println "Upload successful: ${response.json}"
    
} catch (GroovyHttpClient.HttpResponseException e) {
    if (e.statusCode == 413) {
        println "File too large"
    } else if (e.statusCode == 400) {
        println "Invalid file format"
    } else {
        println "Upload failed: ${e.message}"
    }
} catch (IOException e) {
    println "Network error: ${e.message}"
}
----

=== Validation Errors

Handle server-side validation:

[source,groovy]
----
def response = client.postMultipartSync("/upload") {
    part {
        name "file"
        filename "data.txt"
        data fileBytes
    }
}

if (!response.isSuccess()) {
    def errors = response.json.errors
    println "Validation failed:"
    errors.each { field, message ->
        println "  ${field}: ${message}"
    }
}
----

=== Retry Configuration

Configure retries for flaky uploads:

[source,groovy]
----
def parts = [MultipartPart.bytes("file", "important.pdf", "application/pdf", pdfBytes)]

client.postMultipartSync("/upload", parts) {
    header "Idempotency-Key", uploadId     // let the server drop a duplicate
    retry {
        maxAttempts 3
        backoffExponential(1000, 5000, true)
        onTimeouts true
        on5xx true
        retryNonIdempotent true            // uploads are POSTs: retries need this opt-in
    }
}
----

NOTE: Retry is configured on the request-configuration closure of the list-based `postMultipart(path, parts) { ... }` form. The part DSL (`postMultipart(path) { part { ... } }`) describes parts only. Since 2.0.0, a POST is retried only with `retryNonIdempotent`.

== Testing Multipart Uploads

=== With HttpClientTestDsl

[source,groovy]
----
def testDsl = HttpClientTestDsl.create()
testDsl.start()

testDsl.when("/upload")
    .respondWith {
        status 201
        json([uploaded: true, filename: "test.txt"])
    }

def client = new GroovyHttpClient(testDsl.baseUrl)

def response = client.postMultipartSync("/upload") {
    part {
        name "file"
        filename "test.txt"
        content "Hello, World!"
    }
}

assert response.statusCode == 201
assert response.json.uploaded == true

testDsl.verify("/upload") {
    wasCalled(1)
    withMethod("POST")
    withHeader("Content-Type")  // Contains multipart/form-data
}

testDsl.stop()
----

=== With MockHttpServer

[source,groovy]
----
def server = new MockHttpServer()
server.init()

server.addRequestCheck("POST", "/upload", 200)
    .withExpectedMultipart([
        [name: "file", filename: "test.txt", content: "Hello!".bytes],
        [name: "description", content: "Test file".bytes]
    ])
    .withResponseBody('{"success":true}')

def client = new GroovyHttpClient("http://localhost:${server.port}")

def response = client.postMultipartSync("/upload") {
    part {
        name "file"
        filename "test.txt"
        content "Hello!"
    }
    part {
        name "description"
        content "Test file"
    }
}

assert response.statusCode == 200

server.shutdown()
----

[NOTE]
====
MockHttpServer validates multipart requests by checking:

* Part names match expected
* Filenames match (if specified in expectations)
* Content matches byte-for-byte
* Content-Types match (if specified)
====

== Best Practices

=== Choose the Right API

[horizontal]
*DSL*:: Inline, ad-hoc uploads with few parts
*Static*:: Programmatic, reusable upload logic
*Hybrid*:: Static parts + DSL configuration

[source,groovy]
----
// ✅ DSL: Simple, inline
client.postMultipartSync("/upload") {
    part { name "file"; filename "doc.pdf"; data bytes }
}

// ✅ Static: Reusable, composable
def parts = buildUploadParts(files)
client.postMultipartSync("/upload", parts)

// ✅ Hybrid: Combine both
client.postMultipartSync("/upload", parts) { config ->
    config.header "Authorization", token
}
----

=== Always Set Content-Type

[source,groovy]
----
// ✅ Explicit content type
part {
    name "file"
    filename "data.csv"
    contentType "text/csv; charset=UTF-8"
    data csvBytes
}

// ❌ Missing content type (defaults to text/plain)
part {
    name "file"
    data csvBytes
}
----

=== Use Meaningful Filenames

[source,groovy]
----
// ✅ Descriptive filename
part {
    name "invoice"
    filename "invoice_2025_01_24.pdf"
    data pdfBytes
}

// ❌ Generic filename
part {
    name "invoice"
    filename "file.pdf"  // Not helpful for debugging
    data pdfBytes
}
----

=== Handle Large Files Appropriately

[source,groovy]
----
// ✅ Extended timeout for large files
client.postMultipartSync("/videos", parts) { config ->
    config.timeout Duration.ofMinutes(10)
}

// ❌ Default timeout may be too short
client.postMultipartSync("/videos", parts)
----

=== Validate Before Upload

[source,groovy]
----
// ✅ Validate locally
def file = new File("upload.pdf")
if (!file.exists()) {
    throw new IllegalArgumentException("File not found")
}
if (file.length() > 100_000_000) {
    throw new IllegalArgumentException("File too large (>100MB)")
}
if (!file.name.endsWith(".pdf")) {
    throw new IllegalArgumentException("Only PDF files allowed")
}

// Now upload
def response = client.postMultipartSync("/documents") {
    part {
        name "file"
        filename file.name
        contentType "application/pdf"
        data file.bytes
    }
}
----

## Troubleshooting

=== "Multipart parts are required" Error

[source,groovy]
----
// ❌ Fails: Empty parts list
client.postMultipartSync("/upload", [])

// ✅ Fixed: At least one part
client.postMultipartSync("/upload", [
    MultipartPart.text("field", "value")
])
----

=== Missing Filename

[source,groovy]
----
// The DSL auto-generates a filename if omitted
part {
    name "field"
    content "text data"
    // filename automatically becomes "field.txt"
}

// For the static API, always provide filename for binary parts
MultipartPart.bytes("file", "document.pdf", "application/pdf", bytes)
----

=== Content-Type Issues

[source,groovy]
----
// ✅ Correct: Include charset for text
part {
    name "description"
    contentType "text/plain; charset=UTF-8"
    content "Description text"
}

// ❌ Missing charset for text
part {
    name "description"
    contentType "text/plain"  // Should include charset
    content "Description text"
}
----

=== Boundary Collisions

GroovyHttpClient automatically generates unique boundaries:

[source,groovy]
----
// Boundary format: ----GroovyBoundary{UUID}
// Example: ----GroovyBoundary3f8d9a1b-4e2c-4a5b-9f1e-8c7d3b2a1e0f
----

No manual boundary management required.

=== Header Safety

A part's `name`, `filename` and `contentType` are written into part headers, so they are validated when the part is created. CR, LF or NUL raises `IllegalArgumentException` (a value containing them could start a new header or part), and `"` is percent-encoded as `%22` (RFC 7578 section 4.2). This applies to every way of creating a part: the constructors, `MultipartPart.text/json/bytes` and the `part { ... }` DSL. Take user-supplied file names through `new File(name).name` or similar, so path components don't reach the server either.

## Performance Considerations

[horizontal]
*Memory Usage*:: All parts loaded into memory — avoid very large files
*Network*:: Multipart has overhead vs. direct binary POST
*Retries*:: Not retried by default (POST); with `retryNonIdempotent` the entire payload is retransmitted
*Timeouts*:: Scale timeout with total payload size
