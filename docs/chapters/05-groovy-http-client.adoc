[[groovy-http-client]]
= GroovyHttpClient Deep Dive

== Overview

`GroovyHttpClient` is the core class of this library, providing a fluent Groovy DSL for making HTTP requests. Built on the JDK `HttpClient` (Java 25+) and virtual threads, it delivers enterprise-grade features with an elegant, concise API.

[quote]
____
HTTP requests should read like natural language, not cryptic API calls.
____

=== Architecture

At its core, GroovyHttpClient wraps three key Java components:

[plantuml, client-architecture, svg]
----
@startuml
component "GroovyHttpClient" as client
component "java.net.http.HttpClient" as httpclient
component "Virtual Thread Executor" as executor
component "Circuit Breaker" as breaker
component "Cookie Manager" as cookies
component "SecurityConfig" as config

client --> httpclient
client --> executor
client --> breaker
client --> cookies
config --> client
@enduml
----

[NOTE]
====
Unlike libraries that replace Java's HTTP stack, GroovyHttpClient *wraps* it, ensuring compatibility and leveraging battle-tested HTTP/2 implementation.
====

== Creating a Client

=== Simple Construction

The simplest way to create a client:

[source,groovy]
----
import org.softwood.http.GroovyHttpClient

def client = new GroovyHttpClient("https://api.example.com")
----

This uses `SecurityConfig.defaults(baseUrl)`: verified TLS, no absolute URLs, policy-checked redirects, no automatic retries. (Before 2.0.0 it used the trust-all testing profile.)

=== With SecurityConfig

For production use, always provide explicit configuration:

[source,groovy]
----
import org.softwood.http.SecurityConfig
import org.softwood.http.GroovyHttpClient

def config = SecurityConfig.production("https://api.example.com")
def client = new GroovyHttpClient(config)
----

=== Using Builder

For fine-grained control:

[source,groovy]
----
def client = GroovyHttpClient.builder("https://api.example.com")
    .connectTimeout(Duration.ofSeconds(5))
    .requestTimeout(Duration.ofSeconds(30))
    .allowRedirects(true)
    .maxRedirects(3)
    .failureThreshold(5)
    .maxResponseBytes(50_000_000L)
    .sslContext(privateCaContext)     // optional: verified TLS against your own trust material
    .build()
----

[TIP]
====
The builder approach is convenient when you need to customize just a few settings without creating a full `SecurityConfig`.
====

== HTTP Methods

GroovyHttpClient supports all standard HTTP methods with both synchronous and asynchronous APIs.

=== GET Requests

*Synchronous*:
[source,groovy]
----
def response = client.getSync("/users/123")

println "Status: ${response.statusCode}"
println "Body: ${response.body}"
----

*Asynchronous*:
[source,groovy]
----
import java.util.concurrent.CompletableFuture

CompletableFuture<HttpClientResponse> future = client.get("/users/123")

future.thenAccept { response ->
    println "Got response: ${response.statusCode}"
}.exceptionally { error ->
    println "Request failed: ${error.message}"
    null
}
----

=== POST Requests

*With String Body*:
[source,groovy]
----
def jsonBody = '{"name": "Alice", "email": "alice@example.com"}'

def response = client.postSync("/users", jsonBody) {
    header "Content-Type", "application/json"
}
----

*With JSON DSL*:
[source,groovy]
----
def response = client.postSync("/users", null) {
    json([
        name: "Alice",
        email: "alice@example.com",
        roles: ["user", "admin"]
    ])
}
----

[NOTE]
====
When using the `json { }` DSL, the `Content-Type: application/json` header is set automatically.
====

=== PUT Requests

[source,groovy]
----
def response = client.putSync("/users/123", null) {
    json([
        name: "Alice Smith",
        email: "alice.smith@example.com"
    ])
}

assert response.statusCode == 200
----

=== PATCH Requests

[source,groovy]
----
def response = client.patchSync("/users/123", null) {
    json([email: "newemail@example.com"])
}
----

=== DELETE Requests

[source,groovy]
----
def response = client.deleteSync("/users/123")
assert response.statusCode == 204
----

=== HEAD Requests

[source,groovy]
----
def response = client.headSync("/users/123")

// Check if resource exists
if (response.statusCode == 200) {
    println "Content-Length: ${response.getHeader('Content-Length')}"
}
----

=== OPTIONS Requests

[source,groovy]
----
def response = client.optionsSync("/users")

def allowedMethods = response.getHeader("Allow")
println "Supported methods: $allowedMethods"
----

== Request Configuration DSL

All request methods accept an optional configuration closure:

[source,groovy]
----
def response = client.getSync("/search") {
    // Query parameters
    query(q: "groovy", limit: 10)
    
    // Headers
    header "Accept", "application/json"
    header "X-API-Key", apiKey
    
    // Timeout override
    timeout Duration.ofSeconds(60)
    
    // Cookies
    cookie "session", sessionId
    
    // Retry override
    retry {
        maxAttempts 5
        backoffExponential(500, 5000, true)
    }
}
----

.Request DSL methods
[cols="2,3"]
|===
|Method |Effect for this request

|`query(Map)` |Append query parameters (URL-encoded)
|`header(name, value)` |Add a header value
|`setHeader(name, value)` |Replace every value of a header, default headers included
|`cookie(name, value)` / `cookies(Map)` |Send cookies; names and values are validated against RFC 6265
|`form(Map)` / `json(obj)` |Set a URL-encoded or JSON body and its Content-Type
|`timeout(Duration)` |Override the configured request timeout
|`version(HttpClient.Version)` |Prefer an HTTP version
|`expectContinue(boolean)` |Send `Expect: 100-continue`
|`retry { ... }` |Override the retry policy
|===

NOTE: Calling anything else inside the closure throws `MissingMethodException`. Before 2.0.0, unknown calls were forwarded to an internal builder that was never sent, so settings such as `timeout(...)` were silently lost.

=== Query Parameters

*Single Parameters*:
[source,groovy]
----
client.getSync("/search") {
    query(q: "groovy", limit: 10, offset: 0)
}
// → /search?q=groovy&limit=10&offset=0
----

*Array Parameters*:
[source,groovy]
----
client.getSync("/articles") {
    query(tags: ["groovy", "http", "client"])
}
// → /articles?tags=groovy&tags=http&tags=client
----

*Map of Lists*:
[source,groovy]
----
def params = [
    status: ["published", "draft"],
    author: ["alice"]
]

client.getSync("/articles") {
    query(params)
}
// → /articles?status=published&status=draft&author=alice
----

[IMPORTANT]
====
Query parameters are automatically URL-encoded. Don't encode them yourself or they'll be double-encoded.
====

=== Headers

*Single Header*:
[source,groovy]
----
client.getSync("/data") {
    header "Accept", "application/json"
}
----

*Multiple Values*:
[source,groovy]
----
client.getSync("/data") {
    header "Accept", "application/json"
    header "Accept-Encoding", "gzip, deflate"
    header "X-Custom", "value1"
    header "X-Custom", "value2"  // Multiple values for same header
}
----

*Conditional Headers*:
[source,groovy]
----
client.getSync("/data") {
    if (useAuth) {
        header "Authorization", "Bearer $token"
    }
    if (acceptCompression) {
        header "Accept-Encoding", "gzip"
    }
}
----

=== Cookies

*Single Cookie*:
[source,groovy]
----
client.getSync("/profile") {
    cookie "session", "abc123"
}
----

*Multiple Cookies*:
[source,groovy]
----
client.getSync("/profile") {
    cookies(
        session: "abc123",
        preferences: "dark-mode",
        language: "en"
    )
}
----

[NOTE]
====
Cookies set via the DSL are *per-request*. For persistent cookies across requests, use the automatic cookie manager (see <<cookies,Cookie Management>>).

Cookie names must be RFC 6265 tokens and values cookie-octets: no `;`, `,`, whitespace, quotes, backslash or control characters. Anything else raises `IllegalArgumentException`, so a value can't smuggle in extra cookies. URL-encode or Base64 values that need those characters.
====

=== Form Data

*URL-Encoded Forms*:
[source,groovy]
----
def response = client.postSync("/login", null) {
    form(
        username: "alice",
        password: "secret123",
        remember: "true"
    )
}
// Content-Type: application/x-www-form-urlencoded
----

*With Custom Charset*:
[source,groovy]
----
import java.nio.charset.Charset

client.postSync("/data", null) {
    form(
        [text: "こんにちは"],
        Charset.forName("UTF-8")
    )
}
----

=== JSON Bodies

*From Map*:
[source,groovy]
----
client.postSync("/users", null) {
    json([
        name: "Alice",
        age: 30,
        roles: ["admin", "user"],
        metadata: [
            created: "2025-01-24",
            source: "api"
        ]
    ])
}
----

*From String*:
[source,groovy]
----
def jsonString = '{"name":"Alice","age":30}'

client.postSync("/users", null) {
    json(jsonString)
}
----

*From Object*:
[source,groovy]
----
class User {
    String name
    int age
    List<String> roles
}

def user = new User(name: "Alice", age: 30, roles: ["admin"])

client.postSync("/users", null) {
    json(user)  // Uses JsonOutput.toJson()
}
----

=== Custom Request Timeout

Override the default request timeout:

[source,groovy]
----
// Default: 30 seconds (from SecurityConfig)
def response = client.getSync("/fast-endpoint")

// Override: 5 seconds for this request
def response2 = client.getSync("/fast-endpoint") {
    timeout Duration.ofSeconds(5)
}

// Override: 2 minutes for slow endpoint
def response3 = client.getSync("/slow-report") {
    timeout Duration.ofMinutes(2)
}
----

[WARNING]
====
Setting very long timeouts can cause resource exhaustion under load. Use judiciously and consider circuit breaker implications.
====

== Response Handling

=== Response Object

All requests return an `HttpClientResponse` object:

[source,groovy]
----
def response = client.getSync("/users/123")

// Properties
int statusCode = response.statusCode
String body = response.body
byte[] bytes = response.bytes
Map<String, List<String>> headers = response.headers
String contentType = response.contentType
Charset charset = response.charset
----

=== Status Code Checks

[source,groovy]
----
if (response.isSuccess()) {
    println "Success! (2xx)"
} else if (response.isClientError()) {
    println "Client error (4xx)"
} else if (response.isServerError()) {
    println "Server error (5xx)"
}

// Direct checks
if (response.statusCode == 404) {
    println "Not found"
}
----

Helper methods:
* `isSuccess()` — 200-299
* `isClientError()` — 400-499
* `isServerError()` — 500-599

=== Header Access

[source,groovy]
----
// Get single header value
String contentType = response.getHeader("Content-Type")

// Get all values for header (multi-value headers)
List<String> setCookies = response.getHeaders("Set-Cookie")

// Check if header exists
if (response.hasHeader("ETag")) {
    String etag = response.getHeader("ETag")
}

// Case-insensitive lookup
String auth = response.getHeader("AUTHORIZATION")  // Works
----

=== JSON Responses

*Automatic Parsing*:
[source,groovy]
----
def response = client.getSync("/users/123")

// Requires Content-Type: application/json
def user = response.json

println "Name: ${user.name}"
println "Email: ${user.email}"
----

*Safe Parsing*:
[source,groovy]
----
def json = response.jsonOrNull

if (json) {
    // Successfully parsed
} else {
    // Not JSON or parse failed
    println "Response was not JSON"
}
----

*Require JSON*:
[source,groovy]
----
try {
    def user = response.requireJson()
    // Throws if not JSON
} catch (ContentParseException e) {
    println "Expected JSON but got: ${response.contentType}"
}
----

[IMPORTANT]
====
JSON parsing is *content-type aware*. The response must have:

* `Content-Type: application/json`
* `Content-Type: application/vnd.api+json`
* Or any type containing `+json`

Otherwise, `json` property throws `ContentParseException`.
====

=== XML Responses

Similar to JSON, but for XML:

[source,groovy]
----
def response = client.getSync("/users/123.xml")

def user = response.xml
println "Name: ${user.name.text()}"

// Or safe parsing
def xmlOrNull = response.xmlOrNull
if (xmlOrNull) {
    // Parse successful
}

// Or require
def xmlRequired = response.requireXml()
----

XML is parsed using Groovy's `XmlSlurper` and requires:

* `Content-Type: application/xml`
* `Content-Type: text/xml`
* Or any type containing `+xml`

=== Binary Responses

Access raw bytes:

[source,groovy]
----
def response = client.getSync("/files/document.pdf")

byte[] pdfBytes = response.bytes

// Save to file
new File("document.pdf").bytes = pdfBytes

// Get size
println "Downloaded ${pdfBytes.length} bytes"
----

[[cookies]]
== Cookie Management

GroovyHttpClient includes automatic cookie management via `java.net.CookieManager`.

=== Automatic Cookies

Cookies from responses are automatically stored and sent on subsequent requests:

[source,groovy]
----
// Server sends: Set-Cookie: session=abc123; Path=/
def login = client.postSync("/login", null) {
    form(username: "alice", password: "secret")
}

// Cookie automatically included in next request
def profile = client.getSync("/profile")
// → Cookie: session=abc123
----

=== Adding Cookies

*Fluent API*:
[source,groovy]
----
client.addCookie("session", "abc123", "/")
client.addCookie("preferences", "dark-mode", "/")

def response = client.getSync("/profile")
// Cookies sent automatically
----

*Using HttpCookie*:
[source,groovy]
----
import java.net.HttpCookie

def cookie = new HttpCookie("session", "abc123")
cookie.path = "/"
cookie.domain = "api.example.com"
cookie.maxAge = 3600
cookie.secure = true

client.addCookie(cookie)
----

=== Retrieving Cookies

[source,groovy]
----
// Get all cookies for this client's host
List<HttpCookie> cookies = client.cookies

cookies.each { cookie ->
    println "${cookie.name} = ${cookie.value}"
}

// Get specific cookie
HttpCookie session = client.getCookie("session")
if (session) {
    println "Session: ${session.value}"
}
----

=== Removing Cookies

[source,groovy]
----
// Remove specific cookie
client.removeCookie("session")

// Clear all cookies
client.clearCookies()
----

=== Cookie Policies

Change how cookies are accepted:

[source,groovy]
----
import java.net.CookiePolicy

// Accept all cookies
client.setCookiePolicy(CookiePolicy.ACCEPT_ALL)

// Accept only from original server (default)
client.setCookiePolicy(CookiePolicy.ACCEPT_ORIGINAL_SERVER)

// Reject all cookies
client.setCookiePolicy(CookiePolicy.ACCEPT_NONE)

// Get current policy
CookiePolicy policy = client.cookiePolicy
----

[TIP]
====
For testing scenarios with multiple domains, use `ACCEPT_ALL`. For production, use `ACCEPT_ORIGINAL_SERVER` (default).
====

== Default Headers

Set headers that apply to all requests:

=== Setting Default Headers

*Single Header*:
[source,groovy]
----
client.setHeader("User-Agent", "MyApp/1.0")
client.setHeader("Accept", "application/json")

// Now all requests include these headers
def response = client.getSync("/data")
----

*Multiple Headers*:
[source,groovy]
----
client.setHeaders([
    "User-Agent": "MyApp/1.0",
    "Accept": "application/json",
    "Accept-Encoding": "gzip"
])
----

=== Adding to Default Headers

[source,groovy]
----
// Set initial header
client.setHeader("X-App-Version", "1.0")

// Add another value for same header
client.withHeader("X-App-Version", "1.0.1")

// Result: X-App-Version sent with both values
----

=== Clearing Default Headers

[source,groovy]
----
client.clearHeaders()
----

=== Viewing Default Headers

[source,groovy]
----
Map<String, List<String>> headers = client.defaultHeaders

headers.each { name, values ->
    println "$name: ${values.join(', ')}"
}
----

[IMPORTANT]
====
Per-request headers (set in DSL) *override* default headers with the same name. They don't merge.

[source,groovy]
----
client.setHeader("Accept", "application/json")

// This request uses text/html, not application/json
client.getSync("/page") {
    header "Accept", "text/html"
}
----
====

== Downloading Files

=== Binary Downloads

*Synchronous*:
[source,groovy]
----
byte[] fileData = client.downloadBytesSync("/files/document.pdf")

new File("document.pdf").bytes = fileData
----

*Asynchronous*:
[source,groovy]
----
client.downloadBytes("/files/large-file.zip").thenAccept { bytes ->
    new File("large-file.zip").bytes = bytes
    println "Downloaded ${bytes.length} bytes"
}
----

=== With Custom Timeout

[source,groovy]
----
// 5 minute timeout for large download
byte[] data = client.downloadBytesSync(
    "/files/huge-file.zip",
    Duration.ofMinutes(5)
)
----

=== Streaming Large Files

For very large files, avoid loading entirely into memory:

[source,groovy]
----
def response = client.getSync("/files/huge-file.zip")

new File("huge-file.zip").withOutputStream { out ->
    out.write(response.bytes)
}
----

[WARNING]
====
`downloadBytes()` and `response.bytes` load the entire response into memory. For files exceeding a few hundred MB, consider using Java's `HttpClient` directly with `BodyHandlers.ofInputStream()`.
====

== Error Handling

=== HTTP Error Responses

Responses with status >= 400 fail with `HttpResponseException`, after any retries. The `*Sync` methods throw the underlying exception directly. The async methods complete their `CompletableFuture` exceptionally, so `future.get()` wraps it in `ExecutionException`:

[source,groovy]
----
try {
    def response = client.getSync("/nonexistent")
} catch (GroovyHttpClient.HttpResponseException e) {
    println "HTTP Error ${e.statusCode}"
    println "Response body: ${e.responseBody}"   // full body; the message holds only a short snippet
    
    if (e.statusCode == 404) {
        println "Resource not found"
    } else if (e.statusCode >= 500) {
        println "Server error"
    }
}
----

NOTE: Before 2.0.0 the `*Sync` methods threw `ExecutionException` and put the whole response body in the exception message.

=== Network Errors

[source,groovy]
----
import java.io.IOException
import java.net.http.HttpTimeoutException

try {
    def response = client.getSync("/data")
} catch (HttpTimeoutException e) {
    println "Request timed out"
} catch (IOException e) {
    println "Network error: ${e.message}"
} catch (java.util.concurrent.TimeoutException e) {
    println "Gave up waiting (the getSync timeout argument)"
}
----

=== Policy Errors

[source,groovy]
----
try {
    client.getSync("/download")
} catch (GroovyHttpClient.RedirectRejectedException e) {
    // redirect to a host outside allowedHosts, HTTPS -> HTTP, or more than maxRedirects hops
} catch (GroovyHttpClient.HttpResponseException e) {
    if (e.statusCode == 413) println "Response exceeded maxResponseBytes"
}
----

=== Circuit Breaker Errors

[source,groovy]
----
try {
    def response = client.getSync("/data")
} catch (GroovyHttpClient.CircuitOpenException e) {
    println "Circuit breaker is open - service unavailable"
    // Handle gracefully: return cached data, fallback, etc.
}
----

=== Content Parse Errors

[source,groovy]
----
try {
    def data = response.json
} catch (GroovyHttpClient.ContentParseException e) {
    println "Failed to parse JSON: ${e.message}"
    println "Content-Type was: ${response.contentType}"
}
----

== Retry Policies

Configure automatic retries for failed requests.

=== Per-Client Retry Policy

Set via `SecurityConfig`:

[source,groovy]
----
import org.softwood.http.GroovyHttpClient.RetryPolicy

def retryPolicy = new RetryPolicy.Config().tap {
    maxAttempts(3)
    backoffExponential(200, 2000, true)
    onIoExceptions(true)
    onTimeouts(true)
    on5xx(true)
}.build()

def config = SecurityConfig.production("https://api.example.com")
    .withOverrides([retryPolicy: retryPolicy])

def client = new GroovyHttpClient(config)
----

=== Per-Request Retry Policy

Override retry behavior for specific requests:

[source,groovy]
----
def response = client.getSync("/critical-data") {
    retry {
        maxAttempts 5
        backoffExponential(500, 10000, true)
        onIoExceptions(true)
        onTimeouts(true)
        on5xx(true)
    }
}
----

POST, PATCH and CONNECT are never retried unless the policy opts in. Do that only when the server de-duplicates, e.g. with an idempotency key:

[source,groovy]
----
client.postSync("/orders", orderJson) {
    header "Idempotency-Key", orderId
    retry {
        maxAttempts 3
        on5xx(true)
        retryNonIdempotent(true)
    }
}
----

=== Retry Conditions

*On I/O Exceptions*:
[source,groovy]
----
retry {
    onIoExceptions(true)  // Connection failures, etc.
}
----

*On Timeouts*:
[source,groovy]
----
retry {
    onTimeouts(true)  // Request timeout exceeded
}
----

*On 5xx Errors*:
[source,groovy]
----
retry {
    on5xx(true)  // All 500-599 status codes
}
----

*On Specific Status Codes*:
[source,groovy]
----
retry {
    onStatusCodes([502, 503, 504])  // Only these codes
}
----

=== Backoff Strategies

*Exponential Backoff with Jitter*:
[source,groovy]
----
retry {
    maxAttempts(4)
    // Start at 100ms, double each time, max 8s, with jitter
    backoffExponential(100, 8000, true)
}
// Delays: ~50-100ms, ~100-200ms, ~200-400ms, ~400-800ms
----

*Fixed Delay*:
[source,groovy]
----
retry {
    maxAttempts(3)
    // Always wait 1 second
    backoffExponential(1000, 1000, false)
}
----

*No Retries*:
[source,groovy]
----
retry {
    maxAttempts(1)  // Original attempt only
}
----

[WARNING]
====
PUT and DELETE are idempotent by definition, so they are retried like GET. If your API doesn't honour that, use `maxAttempts(1)` for those calls. POST and PATCH are not retried unless you opt in with `retryNonIdempotent(true)`. Retrying them without server-side de-duplication can cause:

* Duplicate charges
* Multiple record creations
* Data inconsistency
====

== Request Interceptors

Interceptors provide middleware-style request/response processing.

=== Adding Interceptors

[source,groovy]
----
client.addInterceptor { ctx, next ->
    println "→ ${ctx.method} ${ctx.uri}"
    
    return next.call(ctx).thenApply { response ->
        println "← ${response.statusCode}"
        response
    }
}
----

=== Common Use Cases

*Logging Interceptor*:
[source,groovy]
----
client.addInterceptor { ctx, next ->
    def start = System.currentTimeMillis()
    
    return next.call(ctx).thenApply { response ->
        def elapsed = System.currentTimeMillis() - start
        println "${ctx.method} ${ctx.uri} → ${response.statusCode} (${elapsed}ms)"
        response
    }
}
----

*Authentication Interceptor*:
[source,groovy]
----
def authToken = "Bearer xyz123"

client.addInterceptor { ctx, next ->
    // Add an auth header to every attempt (the supplier runs again on each retry)
    def original = ctx.requestSupplier
    ctx.requestSupplier = { ->
        HttpRequest.newBuilder(original.call(), { name, value -> true })
                .setHeader("Authorization", authToken)
                .build()
    }
    return next.call(ctx)
}
----

TIP: For a fixed token, `client.setHeader("Authorization", token)` is simpler. Either way, the header is dropped automatically if a redirect leaves the original origin.

TIP: Don't write retry logic in an interceptor; use a `RetryPolicy`. The client re-runs the whole interceptor chain for each attempt, with `ctx.attempt` set.

*Metrics Interceptor*:
[source,groovy]
----
import java.util.concurrent.atomic.AtomicInteger

def requestCount = new AtomicInteger(0)
def errorCount = new AtomicInteger(0)

client.addInterceptor { ctx, next ->
    requestCount.incrementAndGet()
    
    return next.call(ctx).whenComplete { response, error ->
        // 4xx/5xx arrive here as responses; `error` is a transport or policy failure
        if (error || response?.statusCode >= 400) {
            errorCount.incrementAndGet()
        }
    }
}

// Check metrics
println "Requests: ${requestCount.get()}, Errors: ${errorCount.get()}"
----

=== Interceptor Context

The `RequestContext` object provides:

[cols="2,3"]
|===
|Property |Description

|`method`
|HTTP method (GET, POST, etc.)

|`uri`
|Target URI

|`requestSupplier`
|Closure that builds HttpRequest

|`retryPolicy`
|Active retry policy for this request

|`attempt`
|Current attempt number (1-based)

|`proceed()`
|Optional method to call next interceptor
|===

[NOTE]
====
Interceptors run in the order they were added: the first added is the outermost, so it sees the request first and the response last.

From 2.0.0, interceptors receive 4xx and 5xx responses as ordinary responses. The `HttpResponseException` is raised after retries, outside the interceptor chain.
====

== Lifecycle Management

GroovyHttpClient implements `AutoCloseable` for resource management.

=== Manual Cleanup

[source,groovy]
----
def client = new GroovyHttpClient("https://api.example.com")

try {
    def response = client.getSync("/data")
    // ... use response
} finally {
    client.close()  // Cleanup executor
}
----

=== Try-With-Resources

[source,groovy]
----
new GroovyHttpClient("https://api.example.com").withCloseable { client ->
    def response = client.getSync("/data")
    println response.body
}
// Automatically closed
----

=== Long-Lived Clients

For application-scoped clients:

[source,groovy]
----
@Singleton
class ApiClient {
    private final GroovyHttpClient client
    
    ApiClient() {
        def config = SecurityConfig.production("https://api.example.com")
        this.client = new GroovyHttpClient(config)
    }
    
    def getUser(String id) {
        client.getSync("/users/${id}")
    }
    
    void shutdown() {
        client.close()
    }
}

// Register shutdown hook
Runtime.runtime.addShutdownHook {
    ApiClient.instance.shutdown()
}
----

[IMPORTANT]
====
Don't create a new client for every request. Client creation is relatively expensive (thread pool setup, SSL context initialization). Reuse clients across requests.
====
